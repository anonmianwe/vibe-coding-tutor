## Problems and fixes
| Problem | How it was fixed |
|---|---|
| The Google Drive connector couldn't open the rules PDF ("not found") | Downloaded it from the public Drive download link instead |
| Node.js wasn't installed, and the Chrome extension wasn't connected, so the app couldn't be tested the usual way | Ran Chrome in headless mode with a test page that clicks through every screen and checks the results |
| The test server's port (8765) was already in use | Ran it on another port (8799) |
| The ◐ theme icon didn't show in the font | Replaced it with a small drawn (SVG) icon |
| Changing a setting during a quiz restarted the quiz | The app now waits until the quiz is finished before redrawing the screen |
| After the rebuild, the "💡 ดูเฉลย" (solution) button was visible from the start, which would let students skip every puzzle. The automated test missed it because it only checked the `hidden` attribute | Found it in a screenshot. The `.btn` style overrode `hidden`, so a CSS rule now always hides hidden elements. The test now checks what's actually visible on screen |
| The C syntax notes in the tips contain literal braces like `{ }`, but the hard-word markup `{คำ}` treated them as words and deleted them, so students would have read the notes with the braces missing | Found by the automated test. The markup now only matches Thai words, and the test checks that the C note still shows `{ }` |
| The automated test crashed on the live GitHub Pages site but passed locally | The page loads slower over the network than the test's fixed 0.9-second wait. The test now waits until the app has drawn its first screen |
| A shell command that edited the test file was blocked by Claude Code's safety check (it could not parse the command) | Put the same edit script in a file and ran it from there; nothing was deleted |
| Live read-aloud (Web Speech API) made no sound on our computer, because it has no Thai voice | Switched to pre-made audio files, so every device sounds the same. The browser voice is only a fallback |
| The computer had no pip, so edge-tts could not be installed | We installed python3-venv (`sudo apt install python3-venv`), and AI installed edge-tts in a temporary virtual environment |
| The voice would read code symbols badly, or skip them (`_`, `;`, `{ }`, `#`) | A symbol on its own is now said by name (for example "เซมิโคลอน", "วงเล็บปีกกาเปิด"); inside code it is dropped (`move();` → "move") |
| The live-room test failed in headless Chrome even though the PeerJS server was reachable | Headless "virtual time" fast-forwards the test's waits before real network replies arrive. The test now runs in real time and posts its result to a small local listener (`?report=<port>`) |
| The AI content review found tips that taught something slightly wrong: "in C every statement ends with ;" (not true for for/if blocks) and "Python must indent 4 spaces" (4 is only the convention) | Reworded the 3 notes, remade their audio, and recorded the review in `docs/AI-content-and-tools.md` |
| The README still had a placeholder instead of the real live link | Replaced it with https://anonmianwe.github.io/vibe-coding-tutor/ |
